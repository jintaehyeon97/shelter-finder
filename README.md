# 🌡️ 폭염 안전 지도 (Heatwave Safety Map)

폭염 시 현재 위치 기준으로 주변 편의점·무더위쉼터를 지도에서 찾고, 태양 위치 기반 그늘 추정과 실시간으로 갱신되는 도보/대중교통 경로를 안내해주는 위치 기반 안전 지원 앱입니다.

React Native(Expo) 앱과 Node.js/Express 백엔드로 구성된 풀스택 개인 프로젝트입니다.

---

## 배경

폭염이 심해지는 여름, 밖에 있을 때 가장 가까운 그늘/쉼터가 어디인지 빠르게 알기 어렵다는 문제의식에서 시작했습니다. 처음엔 "편의점 재고 확인 앱"으로 기획했지만, 개발 과정에서 실제로 더 필요한 건 "폭염 상황에서 안전하게 대피할 곳을 찾는 것"이라고 판단해 방향을 전환했습니다.

## 핵심 기능

- 🗺️ **전국 편의점 + 무더위쉼터 지도** — 카테고리별 필터 토글
- 📍 **현재 위치 기반 반경 검색** — 편의점은 카카오 로컬 API 실시간 조회, 쉼터는 PostGIS 공간 쿼리
- 🔍 **통합 검색 / 거리순 추천 리스트**
- 🧭 **도보·대중교통 경로 안내** — 실시간 위치 갱신에 따라 경로 자동 재계산
- 🌳 **그늘 경로 추정** — 태양 고도·방위각을 직접 계산해 건물 그림자가 도로를 덮을 가능성을 추정하고, 경로를 그늘/노출 구간으로 색칠

## 아키텍처

```
┌─────────────────────┐        ┌──────────────────────┐        ┌─────────────────┐
│  React Native (Expo) │  REST  │  Express (Node.js/TS) │  SQL   │  PostgreSQL      │
│  conbini-app         │ ─────▶ │  conbini-backend       │ ─────▶ │  + PostGIS       │
└─────────────────────┘        └──────────┬───────────┘        └─────────────────┘
                                           │                        (무더위쉼터 데이터)
                     ┌─────────────────────┼─────────────────────────┐
                     ▼                     ▼                         ▼
              공공데이터포털 API      TMAP(SK Open API)          카카오 로컬 API
              (무더위쉼터/공원)     (도보·대중교통 경로)      (편의점 실시간 조회/검색)
```

> 편의점 데이터는 초기엔 공공데이터를 DB에 적재하는 방식으로 만들었다가, 데이터가 최대 1년까지 오래돼 폐업한 곳도 계속 표시되는 문제를 겪은 뒤 **카카오 로컬 API로 매 요청마다 실시간 조회하는 방식**으로 전환했습니다. 관련 과정은 아래 "기술적으로 흥미로웠던 문제들" 참고.

## 기술적으로 흥미로웠던 문제들

### 1. 공공데이터 좌표계 오판
공공데이터의 좌표(x, y)가 국내 표준 좌표계(EPSG:5179)일 거라 가정하고 변환했는데, 결과 좌표가 전부 한국 밖으로 튀는 문제가 있었습니다. 값의 크기를 역산해보니 실제로는 **Web Mercator(EPSG:3857)** 좌표였고, 변환 공식을 바꾸자 바로 해결됐습니다. 이후 모든 공공데이터 시딩 스크립트에 좌표 범위 검증 로직을 추가했습니다.

### 2. react-native-maps의 Android 렌더링 버그
필터를 토글하거나 같은 경로를 다시 요청했을 때, 지도 위 마커/경로선이 사라지지 않거나 흐릿하게 남는 현상이 있었습니다. 원인은 React가 컴포넌트를 "새로 마운트" 대신 "속성만 업데이트"로 처리할 때 Android 네이티브 지도 레이어가 이를 제대로 반영하지 못하는 문제였습니다. `key`에 매번 바뀌는 버전 번호를 포함시켜 강제로 리마운트되도록 해 해결했습니다.

### 3. 그늘 추정: 태양 위치 계산으로 건물 그림자 근사
"그늘이 많은 경로"를 추천하려면 그늘 데이터가 필요한데, 국내엔 그런 공개 데이터가 없습니다. 대신 **태양의 고도·방위각을 직접 계산**(SunCalc 알고리즘 기반)하고, 도로 방향과 태양 방향의 기하학적 관계로 "건물 그림자가 도로를 가로지를 가능성"을 근사했습니다. 도로가 태양과 수직에 가까울수록, 태양 고도가 낮을수록 그림자가 도로를 덮을 확률이 높다는 원리를 이용했습니다.

### 4. 오래된 공공데이터의 정합성 문제 → 실시간 조회로 전환
편의점 공공데이터가 최대 1년 전 기준이라, 이미 폐업한 곳도 마커로 계속 표시되는 문제가 있었습니다. 처음엔 **카카오 로컬 API로 DB의 전체 데이터를 대조 검증하는 배치 스크립트**(반경 내 존재 여부 확인 → 2회 연속 미검색 시 숨김)로 접근했는데, 실제로 테스트해보니 "반경 안에 아무 편의점이나 있으면 통과"하는 방식이라 **폐업한 특정 매장 대신 근처 다른 매장이 잡혀 오탐이 나는 한계**가 있었습니다.

결국 "우리 DB에 스냅샷을 저장해두고 검증"하는 접근 자체를 재고해, **편의점 조회/검색 요청이 올 때마다 카카오 로컬 API를 직접 호출**하는 방식으로 전환했습니다. 데이터 소스를 실시간 조회로 바꾸니 "오래된 스냅샷"이라는 문제 자체가 사라졌고, 코드도 오히려 단순해졌습니다(대조 로직, DB 동기화 로직 불필요). 전환 이후 필요 없어진 시딩/검증 스크립트와 `convenience_stores` 테이블은 깔끔하게 제거했습니다.

이 과정에서 흥미로운 버그도 하나 잡았습니다: 기존 라우트가 DB(`db.ts`)를 거치면서 그 파일 안의 `dotenv.config()` 호출에 "우연히" 편승해 환경변수가 로딩되고 있었는데, DB 의존성을 제거하자 그 우연한 순서가 깨지면서 카카오 API 키를 못 읽는 문제가 발생했습니다. 각 모듈이 자기 환경변수를 스스로 안전하게 로딩하도록 고쳐 해결했습니다.
